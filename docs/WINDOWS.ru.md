# Glowline для Windows 11

[English](WINDOWS.md) · [Проект](../README.md)

Исходники Windows-версии предназначены для **Windows 11 x64**, процессоров AMD и Intel и той же ленты **Skydimo SK0L34 на 112 LED**, что и версия для macOS. Windows 10, другие контроллеры и другая длина ленты не поддерживаются. Windows-порт не входит в опубликованный macOS-релиз 1.2.0.

## Запуск

Распакуйте Windows ZIP в постоянную папку и откройте `Glowline.exe`. Приложение использует компоненты Windows и статически подключённую библиотеку C++; Visual Studio нужна только для разработки. EXE не имеет цифровой подписи.

Завершите другие программы управления лентой. В разделе **Приложение** обновите устройства и выберите **COM-порт** контроллера. Glowline открывает только выбранный порт, без совместного доступа, и проверяет полный ответ SK0L34 до отправки LED-кадров. Программа не меняет прошивку и скорость контроллера. Драйвер USB-порта должен соответствовать архитектуре Windows: x64-приложению на Windows ARM всё равно нужен ARM64-драйвер устройства.

В разделе **Захват экрана** выберите монитор для режима **Экран**. Windows Graphics Capture передаёт линейные кадры RGBA-half; курсор исключён. Защищённое содержимое и защищённый рабочий стол Windows захватывать нельзя. При ошибке захвата вывод очищается и появляется сообщение. Остальные эффекты работают без захвата экрана. Если виртуальный адаптер не поддерживает аппаратный Direct3D, используется системный программный рендерер WARP; производительность при этом может снижаться.

Закрытие окна оставляет Glowline в области уведомлений. Нажмите значок для открытия настроек или выберите **Выйти**. Настройка **Гасить ленту при выходе** управляет последним чёрным кадром. Автозапуск запоминает путь текущего EXE для текущего пользователя Windows; отключите его перед переносом или удалением папки.

## Настройки и профили

В семи разделах доступны девять режимов, независимые настройки эффектов, коррекция цвета, раскладка LED и яркость отдельных сторон, дневное и ночное расписание, частоты захвата и передачи, профили и настройки приложения. Расписание использует местное время Windows. При одинаковом времени начала дня и ночи действует ручная яркость. Текущие настройки сохраняются автоматически; профили — отдельные снимки, которые нужно обновлять самостоятельно.

Интерфейс использует те же семь разделов, подписи и параметры, что и текущая macOS-версия, с тёмной, светлой и системной темами. Ползунки поддерживают стрелки, Home/End и ввод числа; смещение LED меняется по одному шагу. Во время работы расписания ручная яркость недоступна. Отключение стороны блокирует её усиление. Диалоги выбора цвета и файлов, заголовок окна и системные настройки запуска следуют оформлению Windows.

В разделе **Приложение → Открыть диагностику** сохраняется и открывается `diagnostics.txt` рядом с настройками: состояние подключения и захвата, частота, время записи, счётчики кадров и текущие ошибки. Это снимок состояния на момент нажатия.

Настройки находятся в `%LOCALAPPDATA%\Glowline\settings.json`. Импорт и экспорт используют JSON со схемой 1, профилями и параметрами каждого эффекта. USB-путь macOS при импорте в Windows очищается — выберите COM-порт заново. Выбор экрана Windows хранится отдельно в `windowsDisplay`. Повреждённые исходные данные при запуске сохраняются в соседнюю резервную копию. Будущая версия схемы отклоняется без замены файла.

Восстановление ограничено начальной попыткой и тремя повторами через 5, 10 и 20 секунд. После десяти секунд исправной работы бюджет соответствующего восстановления пополняется. **Переподключить** запускает новую попытку сразу. Настройка переподключения управляет автоматическим восстановлением USB-связи.

Экспериментальный переключатель ранней реакции захвата доступен только на macOS.

## Сборка и проверки

Установите Visual Studio 2022 C++ Build Tools с компонентами:

- `Microsoft.VisualStudio.Workload.VCTools`
- `Microsoft.VisualStudio.Component.VC.Tools.x86.x64`
- `Microsoft.VisualStudio.Component.Windows11SDK.26100`
- `Microsoft.VisualStudio.Component.VC.Llvm.Clang`

В корне репозитория выполните:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\build-windows.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\package-windows.ps1
```

Результат — `build\windows-x64\Glowline.exe`. Сборка запускает автономные проверки настроек, расписания, восстановления, цвета и протокола. Они не трогают USB и сохранённые настройки. В интерактивном сеансе Windows доступны дополнительные проверки:

```powershell
.\build\windows-x64\Glowline.exe --ui-test "$env:TEMP\Glowline-ui-report.txt"
.\build\windows-x64\Glowline.exe --capture-test "$env:TEMP\Glowline-capture-report.txt"
```

Проверка захвата временно заполняет основной экран красным и синим. Обе команды записывают отчёт и возвращают ненулевой код при ошибке. Проверкам интерфейса и захвата нужен открытый рабочий стол; они выполняются отдельно от CI без графического сеанса. Сборка x64, проверка ZIP после распаковки, автономные тесты, семь разделов интерфейса и захват красного/синего экрана прошли в Windows 11 ARM через эмуляцию x64. Это не подтверждает производительность, работу USB-драйвера или оптический результат на физическом компьютере AMD/Intel.

GitHub workflow собирает кандидат Windows x64 и сохраняет его в артефактах Actions; релиз автоматически не публикуется.
