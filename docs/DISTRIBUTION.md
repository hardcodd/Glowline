# Distribution preparation

[Русский](DISTRIBUTION.ru.md)

The build and packaging scripts prepare artifacts without automatically publishing a GitHub release or submitting anything to Apple. Version 1.2.0 is distributed with ad-hoc signing and documented per-app Gatekeeper exception steps. Developer ID signing and notarization are recommended to simplify installation; they are not present in this release.

1. The project uses the [MIT License](../LICENSE). Confirm rights for included source/assets before distribution. The unused Skydimo plugin API header is no longer included. Platform frameworks are supplied by macOS; the application bundles no third-party runtime library. Removing a header is not a legal provenance audit of every historical file.
2. Review source changes, increment `VERSION.json` build for a changed binary, and build on Apple Silicon with the minimum supported macOS SDK/runtime available. The bundle identifier stays `local.alex.Glowline` to preserve installed identity. Local self-tests use disposable settings directories; they never open USB or register login items.
3. Run `rtk proxy python3 build.py`. For Developer ID, supply `--sign-identity` with an available Developer ID Application identity. The builder signs the engine first, then the app, with hardened runtime and timestamping for non-ad-hoc identities. A valid certificate and its private key are prerequisites; do not put credentials in source or logs.
4. Run `rtk proxy python3 package.py`. ZIP extraction, bundle signatures, DMG integrity are checked; `--verify-mount` additionally compares read-only mounted DMG contents when the OS permits mounting. `build/distribution/SHA256SUMS` records the final artifact hashes. `manifest.json` records each packaged file's hash. No live settings, logs, exports, backups or source checkout are packaged.
5. With authorization and Apple credentials configured locally, follow [Apple's notarization workflow](https://developer.apple.com/documentation/security/notarizing-macos-software-before-distribution). Submit a Developer ID package using `notarytool`, inspect the result, staple the ticket, validate it and regenerate hashes. Notarization is not performed by these scripts. An ad-hoc package is only a local preview and can fail Gatekeeper.
6. Validate the final downloaded artifact on a clean Mac/account: install, Screen Recording grant/denial/reopen, USB selection, all modes, off/on, profiles, update with preserved data, reconnect, sleep/wake, login after reboot and removal. Test macOS 15 and a second compatible controller before widening compatibility claims. Record checks actually performed; optical calibration is a separate test.

`.github/workflows/check.yml` prepares read-only CI on Apple Silicon macOS 15/26. It builds, runs offline contracts/sanitizers and checks ZIP packaging. It has no release, artifact upload, signing secret or notarization step. See [GitHub Actions](https://github.com/hardcodd/Glowline/actions) for current results. A successful run verifies builds and offline contracts on its runner; it does not verify physical hardware or interactive installation.
